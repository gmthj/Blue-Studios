## Page 6

Web Application :: Minimum Requirements
●
You must identify and solve a problem.
○
This can be either an unsolved problem or an existing problem.
●
You must use HTML, CSS and JavaScript in your implementation.
○
Optionally, you are encouraged to use Bootstrap (or similar CSS framework), JSON, and Vue (or a similar 
JavaScript framework).
●
Your solution must include a responsive design.
●
Your solution must be a dynamic site that interact with a backend data store.
○
This could involve applying knowledge from IS113 (e.g. Express.js + MongoDB), but you are free to choose 
another data storage solution if you prefer (e.g. files, other types of databases, cloud storage).
●
Your solution must make meaningful use of at least one external publicly available API via asynchronous HTTP requests.
●
Your solution must include end-to-end (E2E) testing for all core features.
●
You must utilize GitHub collaboration tools available for your project to effectively manage version control, track changes, 
and facilitate communication among group members.
●
You must deploy your final solution to a remote server (e.g. AWS, Google Cloud, Azure, Firebase, Vercel and etc.) that is 
accessible online.

## Page 23

Frequently Asked Questions (FAQ)
• Are we required to use Bootstrap or Vue.js?
•
No, you are not required to use Bootstrap or Vue.js specifically. However, you are encouraged to use frameworks to 
simplify, standardize, and speed up the development process of your project. 
• I want to use React. Is this allowed?
•
Yes, using React or a similar framework is allowed. However, we strongly encourage you to use Vue.js for the 
following reasons:
•
Technical Support: Vue.js is covered in the syllabus, so we can provide more effective support. React is not 
officially included in the course materials.
•
Exam Preparation: The final exam will include questions on JavaScript and Vue.js, but not on React. Using 
Vue.js will better prepare you for the assessment.
•
Also, consider your group mates’ familiarity with React. If everyone is comfortable with it, using React is fine. 
However, if some group members are not, they would need to learn two different JavaScript frameworks during the 
course. Make sure the whole group is comfortable with this decision.

## Page 24

Frequently Asked Questions (FAQ)
• Can the teaching team provide technical support on on the technology we are using, e.g., Docker, AWS, etc.?
• In general, no. There is a plethora of technologies out there. Given the variability in our expertise with different 
technologies, it would be unfair for us to assist one group with technology we are familiar with while being unable to 
support another group with technology, we are not knowledgeable about. However, we are happy to engage in 
high-level discussions regarding the appropriateness of different technologies for your solution.
• Which browser should we use?
• You can use any browser you prefer. However, for grading purposes, please ensure that your website displays 
properly in Google Chrome. We will also use Chrome’s developer tools to test your site’s responsive design.

## Page 25

Frequently Asked Questions (FAQ)
• Are we allowed to use publicly available code sources (e.g. from GitHub projects)?
• You may use publicly and freely available libraries (i.e., not paid). However, such usage must be clearly identified in 
your presentation and within the comments of your code. You must NOT present this code as your own work, as 
that would constitute plagiarism. If you are unsure, please contact your teaching team to discuss your plans.
• Are all members of a group receiving the same group project grade?
• Yes, a single grade is awarded for the project. However, if a group member is not participating, please inform your 
instructors EARLY, and individual adjustments will be considered on a case-by-case basis. However, if you notify 
your instructors too close to the final deliverable deadline (e.g., one week before), it may be considered too late to 
take any meaningful action, and your instructors may not accept your case.

## Page 28

Frequently Asked Questions (FAQ)
• Can I use dummy data instead of real-data?
• If the type of data your application requires is publicly available, we encourage you to use real data to make your 
prototype more realistic. However, if you anticipate difficulties in obtaining real data, please consult with your 
teaching team for guidance.
• Under “problem solving and solution appropriateness”, are you referring to coding complexity, or more to the business 
side?
• We are referring to the business side, meaning you should clearly articulate the problem your website addresses 
and demonstrate that the implementation effectively solves this problem. The problem does not need to be a critical 
societal issue. For example, a virtual escape room may not address a major societal problem but still solves a 
relevant issue, such as enabling remote connection with friends and family, especially during a pandemic.

## Page 29

Frequently Asked Questions (FAQ)
• Are we allowed to scrape data from a website?
• If you choose to scrape data from a website, you must ensure that you comply with any restrictions outlined in the 
site’s robots.txt file and consider any legal implications. Additionally, you must clearly identify and properly credit the 
sources of your data. Note that using scraped data does not substitute the requirement to utilize at least one 
publicly available API.
• How will the responsive design of our web application be tested?
• We will test your website using Chrome’s developer tools across various viewports, starting from the iPhone 6 to the 
XL breakpoint of Bootstrap. Ensure that your layout looks good and adjusts properly across all viewports within this 
range.

## Page 31

Frequently Asked Questions (FAQ)
• Are we allowed to use AI/LLM in the project?
• Generally, we allow the use of AI/LLM for lower order thinking tasks such as:
• information search
• Generating website concepts, layouts, or themes
• Exploring different UI/UX design inspirations
• Explaining coding errors and debugging hints
• Boilerplate code generation – starter code and code snippets
• Generating unit test cases, sample inputs, or mock data
• You are not allowed to use AI/LLM for higher order thinking tasks such as:
• Core implementation tasks (to implement main business logic, backend endpoints, or critical frontend 
interactivity)
• Problem solving – students must demonstrate their own capability for solving problems and addressing major 
implementation issues, not just rely on automated AI fixes.
• In the README.txt file, state clearly the parts you solely rely on AI/LLM.
